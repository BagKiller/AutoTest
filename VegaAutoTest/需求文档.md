# 一、项目背景

目前芯片检测软件的测试主要依赖人工操作。

每次代码提交后，测试人员需要手动完成：

1. 拉取最新代码

2. 编译项目

3. 启动芯片检测软件

4. 创建或加载 Recipe

5. 配置检测参数

6. 配置设备、相机、Motion 等相关参数

7. 执行检测任务

8. 等待完整扫描流程结束

9. 查看扫描结果

10. 根据本次代码修改内容判断功能是否正常

整个测试链路涉及大量 Windows GUI 操作，包括按钮点击、文本输入、下拉框选择、窗口切换、弹窗处理、DataGrid 操作等。

同时，芯片检测软件具有较复杂的运行状态和较长的任务执行时间，因此传统的固定坐标脚本、简单 UI 自动化脚本难以覆盖完整流程。

---

# 二、项目目标

构建一个基于 AI Agent 的自动化回归测试系统。

系统能够在代码提交后自动：

> **分析代码变更 → 编译 → 启动软件 → 根据变更内容选择测试流程 → 自动操作芯片检测软件 → 执行完整检测 → 验证结果 → 分析异常 → 生成测试报告**

最终实现从代码提交到测试结果输出的自动闭环。

目标不是简单实现“AI 自动点击鼠标”，而是构建一个：

> **AI + 确定性自动化 + GUI 视觉理解 + 软件内部状态 + 测试状态机**

组成的智能测试系统。

# 四、AI 需要解决的核心问题

## 4.1 自动理解代码提交内容

系统需要读取：

- Commit Message

- Git Diff

- 修改文件

- 修改类

- 修改方法

- 修改模块

AI 根据代码变化判断：

- 本次修改属于哪个功能模块

- 哪些功能可能受到影响

- 应该执行哪些测试

- 哪些测试可以跳过

例如：

```text
Commit:

fix: improve wafer edge detection threshold
```

AI 判断：

```text
修改模块：
Wafer Edge Detection

影响功能：
晶圆边缘检测

建议测试：
Wafer Edge Detection Regression Test
```

# 六、GUI 控件定位策略

不能单纯依赖固定坐标。

系统应该采用多级定位机制。

### 第一优先级：Windows UI Automation

通过控件：

- Name

- AutomationId

- ControlType

- ClassName

- Parent/Child Relationship

定位控件。

例如：

```text
Button
Name = "开始检测"
AutomationId = "btnStartScan"
```

直接调用控件操作。

---

### 第二优先级：OCR

如果 UI Automation 无法获取目标控件：

通过 OCR 识别：

```text
开始检测
创建 Recipe
确定
取消
```

根据文字位置定位控件。

---

### 第三级：视觉模型

对于：

- 自绘控件

- 第三方控件

- 图像区域

- UI Automation 无法识别的控件

通过 VLM / GUI Agent 模型分析截图，找到目标控件的 Bounding Box。

例如：

```text
目标：
点击“开始检测”

Vision Model：

bbox = [820, 650, 960, 700]
```

然后由自动化层执行点击。

---

### 第四级：图像模板匹配

对于固定 UI 元素，可以使用 OpenCV Template Matching 作为补充。

# 十、测试结果验证

测试结果应该尽可能采用确定性规则进行验证。

> **2026-09-22 实施修订**：Vega 是**缺陷检测**模型，数据模型里没有
> Total Die / OK / NG（那是晶圆分选机的口径）。结果语义是
> `WaferRunInfo` 的以下字段（经 L1 `query/wafer-run` 输出）：
> `IsScanSuccessful` / `IsScanDone` / `IsAnalysisSuccessful` /
> `resultState`（Pass/Fail）/ `EffectiveDefectCount`（有效缺陷数）/
> `FusedDefects`（融合缺陷）/ `CounterInfos`（名值对 counters）。
> 断言示例按此改写；原文的 die 计数口径仅适用于将来的分选机型。

例如：

```text
Expected:

IsScanSuccessful = true
resultState = Pass
EffectiveDefectCount in [1, 1000000]   # 仿真源图噪声量级，>0 防空跑
Scan Time < 600s
```

实际（L1 `query/wafer-run?id=` 返回）：

```text
IsScanSuccessful = true
resultState = Pass
EffectiveDefectCount = 38637
durationSeconds = 86.09
```

则：

```text
PASS
```

而不是完全依赖 AI 判断截图。

# 十二、测试用例需要标准化

系统应该建立一个测试能力库。

例如：

```text
tests/

├── recipe/
│   ├── create_recipe
│   ├── load_recipe
│   ├── save_recipe
│
├── camera/
│   ├── exposure
│   ├── gain
│
├── motion/
│   ├── home
│   ├── move
│   └── scan
│
├── detection/
│   ├── wafer_scan
│   ├── die_detection
│   └── defect_detection
│
└── result/
    ├── result_summary
    ├── defect_count
    └── export_report
```

每个测试用例采用统一 DSL 描述。

例如：

```yaml
test:
  name: wafer_scan_regression

steps:

  - action: launch_app

  - action: create_recipe
    args:
      name: AI_REGRESSION_001

  - action: set_parameter
    target: exposure
    value: 100

  - action: start_scan

  - action: wait_for
    state: scan_completed
    timeout: 600

  - action: verify_result
    expected:
      total_die: 100
      ng_max: 5
```

AI 不需要每次从零开始规划整个操作流程，而是可以组合已有测试能力。
